**Key concepts to know before picking bullets:**
- **Ralph loop:** A continuous autonomy pattern where a headless agent iterates on a task — writing code, running tests, observing output, adjusting — until strict external success criteria are met. Gokulnaath designs these loops and the prompt scaffolding that drives them.
- **Context rotation:** Deliberately resetting or segmenting LLM context windows mid-task to prevent context pollution (where earlier irrelevant content degrades later reasoning). Git and the filesystem serve as the persistent memory layer across rotations.
- **P2P / F2P gates:** Pass-to-Pass (existing tests must keep passing) and Fail-to-Pass (a previously failing test must now pass) — the automated validation gates every submission must clear.
- **Golden-solution PR:** A fully verified pull request that passes all P2P and F2P gates and is accepted as training data.
- **Prompt engineering style here:** Atomic instructions + completion promises — each prompt specifies exactly one task and exactly what done looks like, with no implementation leakage (the prompt must not reveal the solution path).

## AriesView RAG Evaluation — Full Story (for interviews and cover letters)

**What happened:**
- Given task: evaluate how good the RAG retrieval is
- Initial setup had 1-2 documents and small query set
- Initial precision: 0.1x — identified this as measurement methodology problem, NOT pipeline failure
- The 0.1x was because insufficient test coverage made every wrong retrieval tank precision immediately
- Rebuilt evaluation with 15 legal and financial documents
- Created TWO 300-query sets (600 total) grounded in real document content by reading the actual docs
- Final results: recall 93%, precision improved significantly, MRR baseline established
- Insight: the system was not broken — we were measuring it wrong

**If asked "what would you have done to improve the pipeline?"**
- Low precision + high recall = over-retrieving (too many irrelevant chunks)
- Fix 1: Add cross-encoder reranker (Cohere Rerank, BGE Reranker) to rescore chunks
- Fix 2: Reduce top-k retrieval count
- Fix 3: Tune hybrid retrieval alpha (BM25 vs dense embedding weight)
- Fix 4: Improve chunking — smaller chunks with better overlap
- Fix 5: Query expansion / HyDE for the 7% recall miss
- Fix 6: Domain-specific embeddings (FinBERT for financial docs)
